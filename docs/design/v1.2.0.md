# v1.2.0 — 模拟器嫌疑检测

- 日期：2026-08-17
- 状态：已实现
- 上一版本：[v1.1.0](./v1.1.0.md)
- 变更性质：MINOR（新增检测能力维度，指纹算法不变）

## 一、版本目标

在 v1.1.0 基础上新增「模拟器 / 开发者工具」嫌疑检测维度。
借鉴数美 / 顶象「多特征联合打分」思路，基于已采集的 device / window / webgl
三个维度做规则判定，输出嫌疑分与结论，辅助指纹结果解读。

> 说明：静态规则只能给「嫌疑分」，商用级判定靠指纹库比对 + 模型。本功能定位学习参考。

## 二、检测规则（强 → 弱）

| 信号 | 判定 | 加分 | 依据 |
|---|---|---|---|
| devtools | `platform === 'devtools'` | +100 | 开发者工具直出 |
| emu_abi | abi 含 `x86` / `emulator` | +60 | 真机几乎全为 arm 架构 |
| soft_renderer | renderer 含 `swiftshader` / `llvmpipe` / `basic render` | +70 | 无 GPU 软件渲染 |
| angle_gpu | renderer 含 `ANGLE` 且 vendor 为桌面 GPU（intel/microsoft/amd/nvidia） | +40 | 宿主显卡透传 |
| emu_model | model 含 `sdk_gphone` / `emulator` / `android sdk built` / `unknown` | +50 | 模拟器型号关键字 |
| weak_bench | 0 < benchmarkLevel < 20 | +30 | 跑分异常低 |
| no_safearea | 无 safeArea 且窗口高 > 0 | +15 | PC 显示器/无刘海 |

### 结论映射
- `score >= 90` → `likely_emulator`
- `score >= 40` → `suspicious`
- 其余 → `real_device`

输出结构：`{ verdict, score, signals: string[] }`（signals 为命中项的人类可读描述）。

## 三、指纹影响

- 新增 `categories.simulator` 进入指纹种子 → **本版 fpId 与 v1.1.0 不可比**（符合 MINOR 约定，算法未改）。
- `FPVersion` 提升为 `1.2.0`。

## 四、已知限制

- 规则为静态启发式，非模型判定；存在漏判（新型模拟器）与误判（低端真机 ABI/跑分异常）可能。
- 开发者工具渲染为宿主机 GPU → renderer 常含 ANGLE，容易被判 `suspicious`，属预期行为。
- 无网络上报，结论仅本地展示。

## 五、涉及文件

- `utils/fingerprint.js`：新增 `detectSimulator`，接入 `collectAll`（在异步维度就绪后计算）。
- `pages/index/index.js`：`CATEGORY_META` 新增 `simulator` 分组（置于列表末尾）。

## 六、验证方式

- 开发者工具：`platform=devtools` → verdict 应为 `likely_emulator`（或 `suspicious`）。
- 真机：正常手机 → `real_device`；Android x86 模拟器 → 命中 abi/renderer → 高嫌疑。
- 复制 JSON 中包含 `simulator` 分组（verdict / score / signals）。
