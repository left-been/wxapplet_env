# v1.2.1 — 指纹稳定性修复：动态维度移出指纹种子

- 日期：2026-08-17
- 状态：已实现
- 上一版本：[v1.2.0](./v1.2.0.md)
- 变更性质：PATCH（缺陷修复；不新增维度、不改算法）

## 一、问题背景

真机上**每次重新采集 fpId 都变化**。根因：fpId 把全部维度哈希入种子，其中三个是动态维度：

| 维度 | 变化原因 |
|---|---|
| battery | 电量逐次下降、充电状态随时变 |
| sensors | 加速度计/陀螺仪 x/y/z、罗盘方向是瞬时读数 |
| network | wifi/4G/5G 切换、信号强度波动 |

哈希具有雪崩特性，任一字段变化即整体不同 → 同设备无法得到稳定指纹。

## 二、修复方案

- 定义 `DYNAMIC_FP_KEYS = ['battery', 'sensors', 'network']`。
- `generateFpId` 生成种子时**剔除动态维度**，仅哈希静态维度
  （device / window / app / misc / canvas2d / webgl / simulator）。
- 动态维度仍完整保留在 `categories` 中：页面正常展示、复制 JSON 正常导出、模拟器弱信号仍依赖传感器读数 → 仅不入指纹种子。

## 三、指纹影响

- 静态维度不变 → **同设备重复采集 fpId 恒定**（修复目标）。
- `FPVersion` 提升至 `1.2.1`；因种子构成变化，本版 fpId 与 v1.2.0 不可比（PATCH 缺陷修复下的兼容性权衡，通过版本号在种子中显式标注）。

## 四、涉及文件

- `utils/fingerprint.js`：新增 `DYNAMIC_FP_KEYS`，改造 `generateFpId`；`collectAll` 逻辑不变。
- 页面代码无改动。

## 五、验证方式

- 真机连续「重新采集」多次 → fpId 保持不变，同时电池/传感器/网络数值仍在更新。
- 修改微信字体大小等静态环境字段 → fpId 会变（符合预期，属真实环境差异）。
